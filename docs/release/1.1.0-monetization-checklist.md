# Couplemetric 1.1.0 monetization owner checklist

Owner runbook for Phase 2 (native Premium via RevenueCat, Stripe Premium-only, FCM reminders, AI quota). Do steps in order. **[OWNER]** = needs the owner's dashboard login, device or secrets. **[CLAUDE]** = doable from the repo/CLI once values are supplied privately. Never paste secret values into chat, commits or this file.

Prerequisite: plan Task 10 (manifest/Gradle changes, `versionCode 7` / `versionName "1.1.0"`, `google-services` plugin applied only when `google-services.json` exists) must be merged before step 9. `android/app/build.gradle` on this branch still says `versionCode 6` / `1.0.3`.

## 1. Google Play Console

- [ ] **[OWNER]** Play Console → All apps → **Create app** → "Couplemetric", app, free. Package `app.couplemetric.android` is fixed by the first AAB upload; the old `com.omnilife.app` listing cannot be renamed, so Data safety and content rating are redone.
- [ ] **[OWNER]** Upload a signed 1.1.0 AAB to **Testing → Internal testing** (Play requires one upload declaring `com.android.vending.BILLING` before subscriptions can be created).
- [ ] **[OWNER]** **Monetize with Play → Subscriptions → Create subscription**: Product ID `premium`, name "Couplemetric Premium".
- [ ] **[OWNER]** `premium` → **Add base plan** `premium-monthly`: auto-renewing, 1 month, **Grace period 7 days ON**, **Account hold ON**, resubscribe ON → Set prices → USD 4.99 → Activate.
- [ ] **[OWNER]** **Add base plan** `premium-yearly`: 1 year, same grace/hold/resubscribe → USD 24.99 → Activate.
- [ ] **[OWNER]** On each base plan → **Add offer** `free-trial-7d`: eligibility **New customer acquisition**, phase **Free trial, 7 days** → Activate. The paywall shows "7-day free trial" / "Start free trial" only from this offer (`defaultOption.freePhase`).
- [ ] **[OWNER]** **Activate** the subscription. RevenueCat store identifiers become `premium:premium-monthly` and `premium:premium-yearly`.
- [ ] **[OWNER]** **Setup → License testing** → add at least 2 Gmail accounts, response **RESPOND_NORMALLY**. Purchases are free; renewals are accelerated (monthly ≈ 5 min, yearly ≈ 30 min).
- [ ] **[OWNER]** **Setup → API access** → link the Google Cloud project from step 2 → service account → **Manage Play Console permissions** → App permissions: Couplemetric → Account permissions: **View financial data**, **Manage orders and subscriptions** → Invite. Allow up to 24 h to propagate.
- [ ] **[OWNER]** **Testing → Closed testing** → create track → tester email list → promote the AAB → **Start rollout**. Personal accounts created after Nov 13 2023 need **12 opted-in testers for 14 consecutive days** before production access; the clock starts at opt-in. Purchasing testers must also be license testers.

## 3. RevenueCat

- [ ] **[OWNER]** app.revenuecat.com → project → **Apps & providers → + New → Google Play Store**: package `app.couplemetric.android` → upload the step-2 JSON → Save. The Google Play section must show connected.
- [ ] **[OWNER]** **Product catalog → Products → Import** → select `premium:premium-monthly` and `premium:premium-yearly`.
- [ ] **[OWNER]** **Entitlements → + New**: identifier **`premium`** (exactly; `ENTITLEMENT_ID` in `src/lib/revenuecat/reconcile.ts`) → attach both products. Grants are decided by this entitlement id, not by product id.
- [ ] **[OWNER]** **Offerings → + New** identifier **`default`** → packages **Monthly (`$rc_monthly`) → `premium:premium-monthly`** and **Annual (`$rc_annual`) → `premium:premium-yearly`** → **Make current**. Either setup works: the client resolves a package by its identifier first (custom packages named `premium_monthly` / `premium_yearly`), then by product id prefix (`premium_monthly:…`), then by `packageType` MONTHLY/ANNUAL (`$rc_monthly` / `$rc_annual`).
- [ ] **[OWNER]** **Project settings → API keys**: public Android key (`goog_…`) → Vercel `NEXT_PUBLIC_REVENUECAT_ANDROID_KEY`; new **secret** key (`sk_…`, read subscribers) → `REVENUECAT_SECRET_KEY` (used by `GET /v1/subscribers/{id}`).
- [ ] **[OWNER]** **Integrations → Webhooks → + New**: URL `https://omnilife-relationship-optimizer.vercel.app/api/revenuecat/webhook`; **Authorization header value** = fresh 32-byte random string, identical to Vercel `REVENUECAT_WEBHOOK_SECRET` (compared verbatim, no `Bearer`); environment **Sandbox + Production**; all event types.
- [ ] **[CLAUDE]** After deploy, "Send test event": wrong header → 401; right header → `200 {"received":true,...}` and a `billing_events` row (id = `event.id`, provider `revenuecat`); replay → `{"duplicate":true}`.

## 8. Database migration

- [ ] **[OWNER]** Supabase → **Database → Backups** → confirm a fresh backup; note the timestamp.
- [ ] **[CLAUDE]** `node scripts/migrate-v1.1.0.mjs --dry-run` → review 17 statements (`users` columns `billing_trial_ends_at`, `billing_product_id`, `trial_reminder_sent_at`, `reminder_hour_utc`, `push_opt_in`; tables `billing_events`, `push_tokens`, `coaching_usage`; then `ENABLE ROW LEVEL SECURITY` plus a `"Server only: deny all"` policy for `anon, authenticated` on each of the three new tables). Idempotent, additive, one transaction.
- [ ] **[CLAUDE]** With `DATABASE_URL` (and `DATABASE_SSL_CA`) in `.env.local`: `node scripts/migrate-v1.1.0.mjs --apply` → "Applied 17 statements."
- [ ] **[OWNER]** RLS on the new tables is applied by the script, consistent with commit `aac4376` / `supabase_rls_fix.sql` (which covered the older tables, with `subscribers` server-only in the same way). The app connects as `postgres`, which bypasses RLS, and never reads these tables through PostgREST, so the deny-all policy closes the anon/authenticated API surface and no user-facing policy is needed. Verify in Supabase → **Database → Policies** that `billing_events`, `push_tokens` and `coaching_usage` show RLS enabled with the `Server only: deny all` policy.

- [ ] **[OWNER]** Supabase → **Advisors → Security** shows no "RLS disabled" finding.

## 9. Device acceptance (license tester, closed track)

Run steps 1–4 with `NATIVE_BILLING_ENABLED=false` (expect no prices or purchase UI anywhere), then flip (step 10) and run all.

1. [ ] **[OWNER]** Install from the closed-test opt-in link on a license-tester device. Register account A; note `users.id`.
2. [ ] **[OWNER]** Submit the first daily log → notification pre-prompt → Allow. Evidence: `push_tokens` row for A, `users.push_opt_in = true`, `reminder_hour_utc` set.
3. [ ] **[OWNER]** Settings → notifications toggle reflects opt-in; coaching shows the daily quota (Premium 30/day, free 0).
4. [ ] **[OWNER]** Pricing → yearly card shows the **store** price string and "7-day free trial" (from Play, not hard-coded).
5. [ ] **[OWNER]** Buy yearly with the license-tester account ("Test card, always approves") → in-app success. Evidence: RevenueCat → Customers → `A.id`: `premium` active, **Sandbox**, product `premium:premium-yearly`, period `trial`.
6. [ ] **[CLAUDE]** RC → Webhooks → event log: `INITIAL_PURCHASE` → 200; `billing_events` has the id; `users` A: `subscription_tier='premium'`, `subscription_source='revenuecat'`, `subscription_expires_at` ≈ trial end, `billing_product_id='premium:premium-yearly'`, `billing_trial_ends_at` set.
7. [ ] **[OWNER]** Link partner account B → B's Pricing shows "Included with your partner's Premium"; B's checkout returns 409. Unlink → B is free.
8. [ ] **[OWNER]** Settings → **Manage subscription** opens Play's subscription center (RC `managementURL`). Cancel → app stays Premium until expiry; webhook `CANCELLATION` → 200, DB unchanged.
9. [ ] **[OWNER]** After accelerated expiry (yearly ≈ 30 min) → webhook `EXPIRATION` → A back to `free`, `subscription_source` null. Optionally re-buy with Play's "decline" test card to see `BILLING_ISSUE`: Premium persists until `grace_period_expires_date`.
10. [ ] **[OWNER]** Sign in as A on a second device → Settings → **Restore purchases** → Premium returns without a webhook (server action `syncRevenueCatEntitlement`).
11. [ ] **[CLAUDE]** Set A's `billing_trial_ends_at` to now+48 h, run the workflow manually → push "Your free trial ends in 2 days" arrives, `trial_reminder_sent_at` set; a second run sends nothing.

## 11. Rollback

- [ ] **[OWNER]** Vercel → `NATIVE_BILLING_ENABLED=false` → Redeploy. Paywall, prices and Manage/Restore disappear on next load; no app update needed.
- [ ] Grants are preserved: RC subscriptions keep renewing, the webhook keeps reconciling, and `users.subscription_tier` stays `premium` until RC reports expiry. The flag refunds and revokes nothing.
- [ ] Keep the RC webhook and Play products; deactivating the Play subscription stops new purchases only.
- [ ] No schema rollback: the migration is additive and older code ignores the new columns/tables.
