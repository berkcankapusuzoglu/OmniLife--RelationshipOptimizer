# QA swarm — human-like exploratory testing (web + Android)

Source: GitHub research 2026-10-19 (Sonnet agent). Goal: agents use the app like first-time humans, stress every feature, score polish against Paired / Flamme / Candle, and return structured findings that become fix tasks and regression specs.

## Tooling (adopted)
| Layer | Tool | Install | Use |
|---|---|---|---|
| Web driver (phone viewport) | `vercel-labs/agent-browser` (44k★) + built-in **dogfood** skill | `npm i -g agent-browser && agent-browser install`; `agent-browser skills get dogfood` | `open`, `snapshot -i` (@e refs), `click`, `fill`, `screenshot --annotate`, `set device "iPhone 14"`, `set media dark`, axe audit, `--allowed-domains`, `state save` |
| Geometry / first-timer friction | `averliz/visual-ux-review-toolkit` skills `visual-ux-review`, `ux-flow-walkthrough` | `claude plugin install ui-ux-review@visual-ux-review-toolkit` | tap targets <44px, font size, contrast, layout shift; cognitive walkthrough of multi-step flows |
| Performance | `priyankark/lighthouse-mcp` | `npx lighthouse-mcp` | perf / a11y / SEO scores per route |
| Android exhaustive exploration | `schmidi000/qaos-monkey` (coverage-guided, over callstack/agent-device) | `npm i -D qaosmonkey && npx qaosmonkey init` | one emulator + one test account per run |
| Android deterministic flows | Maestro (`maestro mcp`) + `mobile-next/mobile-mcp` | see master plan | register → log → paywall → purchase |
| Android vision fallback | `droidrun/mobilerun --vision-only` | `uv tool install mobilerun` | when WebView exposes no a11y tree |
| Regression specs | Playwright Test Agents | `npx playwright init-agents --loop=claude` (scratch copy) | turn confirmed findings into specs |
| Crash sweep | `honeynet/droidbot` | pip | deterministic monkey over the APK |

Skipped: appium-mcp (covered), browser-use/stagehand/skyvern (overlap), testdriverai, AppAgent (stale), magnitude (no longer a tester). No repo does competitor-screenshot comparison; we capture Paired/Flamme/Candle screens ourselves and feed a vision rubric.

## Journeys (one agent + one throwaway account each)
1 register/login/password-reset · 2 onboarding · 3 first daily log (quick + detailed) · 4 score reveal / milestones · 5 exercises (free limit) · 6 partner invite/link/challenge (2 accounts) · 7 compare/divergence · 8 insights + optimizer + Pareto · 9 pricing/paywall (stop before payment) · 10 settings/export/referral · 11 delete account · 12 quiz funnel + share/OG · 13 landing/blog/legal · 14 AI coaching gating · 15 streak/weekly calibration.

## Agent prompt skeleton
```
You are a first-time user on a phone (390x844) at <URL>. Journey: <name>. Account: <creds>.
Complete the journey, then stress it: empty submits, boundary values, double-taps, back/forward, refresh mid-flow, offline, dark mode, long text.
Screenshot every distinct screen. Never leave the app domain. Never enter payment details.
Return JSON findings {id, journey, screen, severity, category(functional|ux|visual|a11y|perf|content), repro_steps[], expected, actual, evidence[], confidence} + scorecard.
```
Rubric 0–5 each (evidence required ≤3): functional · UX friction · visual polish vs competitors · accessibility · performance.

## Run modes
(a) Web at phone viewport: agent-browser dogfood per journey (≤5 concurrent), then visual-ux-review per screen, merge `findings.jsonl`, adversarially verify critical/high, rank.
(b) Android emulator: debug APK → Maestro happy paths → mobile-mcp free-form → QAosMonkey exhaustive. Capacitor-specific checks: safe-area overlap, cookie persistence after kill, push prompt timing, hardware back, keyboard covering inputs.
Final reconciler diffs web vs Android findings per journey.

## Cautions
Test accounts only (never admin for destructive flows); `--allowed-domains` on; findings are untrusted data.
